# 交互文档

## 1. 主窗口

```
┌─────────────────────────────────────────────────────────┐
│  VMAF 画质评估工具                                        │
│  ┌───────────────────────────────────────────────────┐  │
│  │ [采集] [卡顿分析] [画质评估] [视频预处理 (绿屏/转码)] ← QTabWidget│  │
│  └───────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

窗口默认 1280×860,四个 Tab 独立工作;采集 Tab 完成后可一键送画质评估。

## 2. 画质评估 Tab

### 2.1 布局

```
┌──────────────────────────────────────────────────────────┐

│ 模型:[vmaf_v0.6.1.json ▼] 线程:[自动] YUV尺寸:[1920x1080]  │
│ [开始评估] [停止]  [██████████████░░░░░░] 62% 1800/2900 帧   │
```

### 2.2 控件交互

| 控件 | 交互 |
|---|---|
| 浏览… | 文件对话框选目标视频;也可由采集 Tab 自动填入截图文件夹 |
| 参考片源 | 只读;自动解析 exe 同级/同级 testdata/上两级 testdata 下的 ai_game_1080p60.mp4,找不到时开始评估报错 |
| 模型 | 下拉列出 exe 同级 `models/*.json` + 内置名 + "自定义 JSON…"(弹文件框) |
| 线程 | 0 = 自动(CPU 核数) |
| YUV尺寸 | 仅输入为 `.yuv` 时生效 |
| 开始评估 | 校验输入 → 启动后台线程(对齐/裁剪全自动,无需人工设置) |
| 停止 | 置原子标志,Pipeline 在当前帧后安全退出 |
| 进度条 | `已处理/总帧数 (百分比)`;采样模式(目标为截图文件夹)下总数 = 匹配对数,未采样参考帧不占进度 |
| VMAF 曲线 | 只画有效样本(丢帧不进图);x 轴视频模式为参考帧号、采样模式为有效样本序号;左键点击 → 日志记录该帧明细;滚轮 → 横轴缩放;右键拖动 → 平移;悬停区域左上角显示帧号+分数 |
| 导出 JSON/CSV | 评估成功后可用;JSON 含逐帧数组,CSV 列为 `ref_frame,dist_frame,status,vmaf` |
| 日志 | 最多保留 5000 行,自动滚底;info 灰白 / warn 黄 / error 红 |

### 2.3 状态与信号流

```
用户点击"开始评估"
  EvalTab.startEval() → 收集 PipelineConfig → new EvalWorker → start()
       │
       │  QThread 内 Pipeline.run()
       ▼
  Worker 信号 ──(QueuedConnection)──► EvalTab 槽
    logMessage        → appendLog (着色 HTML)
    progressChanged   → 进度条
    frameReady        → 曲线 appendFrame/updateFrame
                        日志写分数行
                        缓存帧号/分数到 entries_
    evalFinished      → 结果栏汇总(含帧号覆盖率/冻结段统计) + 启用导出按钮
       │
用户点击曲线
  VmafChartWidget.frameSelected(idx)
       → EvalTab.onChartFrameSelected: 日志记录 entries_[idx] 帧明细
```

### 2.4 异常提示

| 场景 | 行为 |
|---|---|
| 未选文件点开始 | QMessageBox 警告 |
| 视频打不开 | 日志红色错误,结果栏显示失败原因 |
| 帧号识别率不足 80% | 评估失败,提示"请使用 marker_burn 生成片源" |
| 无匹配帧对 | 结果栏"评估失败"(两端帧号无交集) |
| 评估中关窗 | 析构时 requestStop + wait 5s |

## 3. 卡顿分析 Tab

```
┌──────────────────────────────────────────────────────────┐
│ 录屏视频: [____________________] [浏览…]                    │
│ [开始分析] [停止]  [██████████████░░░░░░] 62% 1800/2900 帧   │
│ 录屏 60.00fps / 48.3 秒 / 有效帧 2900 | 平均帧耗时 16.67ms  │
│ 最大 667.00ms | Jank 3 次 / Big Jank 3 次 | 卡顿率 0.10%    │
│ 严重卡顿率 0.10% | Jank/10min 3.7 | 未识别 0 帧  [导出 CSV]  │
│ ┌─ 卡顿事件 ────────────────────────────────────────────┐│
│ │ 时刻(ms)   源帧号   显示耗时(ms)   严重                 ││
│ │ 10233      614      333.3        Big Jank ← 红字      ││
│ └────────────────────────────────────────────────────────┘│
│ ┌─ 日志 ─────────────────────────────────────────────────┐│
│ │[10:23:01] 开始分析                                      ││
│ └────────────────────────────────────────────────────────┘│
└──────────────────────────────────────────────────────────┘
```

| 控件 | 交互 |
|---|---|
| 浏览… | 文件对话框选录屏视频(APK 播放带 QR 帧号片源的画面);记住上次路径 |
| 开始分析 | 校验输入 → 启动 JankWorker 后台线程逐帧解码帧号 |
| 停止 | 置原子标志,当前帧后安全退出 |
| 进度条 | `已解码/总帧数 (百分比)`(总帧数未知时只显示已解码数) |
| 结果区 | fps/时长/有效帧/平均与最大帧耗时/Jank/Big Jank/卡顿率/严重卡顿率/Jank每10min/未识别 |
| 卡顿事件表 | 时刻、源帧号、显示耗时、严重等级;Big Jank 红字;只读不可选 |
| 导出 CSV | 分析成功后可用;每 distinct 帧一行 `seq,frameIndex,displayMs,jank,bigJank`(与 jank_cli 同格式) |

### 3.1 判定与异常

- PerfDog 判定:d > 前 3 个 distinct 帧平均耗时×2 且 d > 84ms → Jank;d > 前 3 均值×2 且 d > 125ms → Big Jank;前 3 帧不判定;片源循环回绕不算卡顿;未识别帧跳过计时
- 帧号识别率 < 80% → 分析失败,明确报错"未检测到足够的帧号标记"
- 评估中关窗 → 析构时 requestStop + wait 5s

### 3.2 信号流

```
用户点击"开始分析"
  JankTab.startAnalysis() → new JankWorker(path) → start()
       │  QThread 内: 逐帧 decodeMarker 收集帧号序列 → analyzeJank()
       ▼
  Worker 信号 ──(QueuedConnection)──► JankTab 槽
    logMessage       → appendLog (着色 HTML)
    progressChanged  → 进度条
    jankFinished     → 结果栏汇总 + 填充卡顿事件表 + 启用导出按钮
```

## 4. 视频预处理 Tab

```
┌──────────────────────────────────────────────────────────┐
│ 原始视频:   [____________________] [浏览…]                  │
│ 输出文件:   [____________________] [浏览…]                  │
│ ffmpeg路径: [____________________] [浏览…]                  │
│ 绿屏标定:   ☑ 片头插入绿屏  [5 秒]                          │
│ 输出分辨率: [1920x1080 (默认 1K) ▼]                         │
│ 视频码率:   [5000 kbps]                                   │
│ ┌─ 生成帧号片源 (逐帧烧录 QR 帧号) ─────────────────────────┐│
│ │ 输入视频: [__________________] [浏览…]                   ││
│ │ 输出文件: [__________________] [浏览…]                   ││
│ │ CRF: [14]  [开始生成]                                    ││
│ └────────────────────────────────────────────────────────┘│
│ [开始处理] [取消]  [████████░░░░░░] 55%                    │
│ ┌─ 日志 ─────────────────────────────────────────────────┐│
│ │[命令] ffmpeg -y -i ...                                  ││
│ │[完成] 处理成功: D:\...\video_processed.mp4               ││
│ └────────────────────────────────────────────────────────┘│
└──────────────────────────────────────────────────────────┘
```

| 控件 | 交互 |
|---|---|
| 原始视频 | 选定后自动生成默认输出名 `原名_processed.mp4` |
| ffmpeg 路径 | 启动时自动查找 PATH;手动可覆盖 |
| 片头插入绿屏 | 勾选 + 秒数(默认 5,范围 1-60) |
| 输出分辨率 | 1080p(默认)/720p/1440p/4K/保持原始 |
| 开始处理 | 先 ffprobe 探测源参数 → 组装命令 → QProcess 执行 |
| 生成帧号片源 | QProcess 调同目录 marker_burn.exe,解析"已处理 N 帧"更新进度 |
| 进度条 | 转码解析 ffmpeg 输出 `time=` 字段;烧码按帧数百分比 |
| 取消 | kill 子进程 |

## 5. CLI 交互

参考视频可缺省(`vmaf_tool.exe --cli dist.mp4`),缺省时自动解析 `ai_game_1080p60.mp4`
(exe 同级 → exe/testdata/ → exe 上两级 testdata/);目标也可以是截图文件夹(采样模式,丢帧恒为 0)。

```

参考视频: 1920x1080 @ 30.00fps

进度 300/300

匹配 240 帧, 丢帧 60, 冻结 0
frame 0 -> 0  vmaf=83.66
...
```
