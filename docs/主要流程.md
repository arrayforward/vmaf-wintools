# 主要流程

## 1. 评估主流程 (Pipeline)

```
开始
 │
 ▼
打开参考视频 ────────────────────────────► 打开目标视频
 │                                          │
 ▼ 第一遍扫描                               ▼ 第一遍扫描
逐帧解码 → 生成 32×32 灰度缩略图            逐帧解码 → 生成 32×32 灰度缩略图
        → 纯色帧标记                                → 纯色帧标记
 │                                          │
 └──────────────┬───────────────────────────┘
                ▼
            帧对齐 (三种模式, 见 §2)
                │  产物: FrameMapping (参考帧 → 目标帧, 或丢帧标记)
                ▼
        解析裁剪区域 (默认中心 1/2)
                ▼
        初始化 VmafEvaluator (模型/线程)
                ▼
 ┌──── 第二遍送帧 (逐参考帧循环) ────┐
 │  读参考帧 (无论是否丢帧都必须读,    │
 │   保持解码顺序!)                   │
 │     │                             │
 │     ├─ 丢帧? → 记录 dropped → 下一帧│
 │     │                             │
 │     ▼                             │
 │  目标解码器前进到匹配帧号            │
 │     │                             │
 │     ▼                             │
 │  两端裁剪 → 尺寸不一致则缩放失真帧   │
 │     │                             │
 │     ▼                             │
 │  vmaf_read_pictures 送帧           │
 │  查询上一帧分数 → 回调 onFrame      │
 │  生成 RGB 缩略图 → 回调预览        │
 └───────────────────────────────────┘
                ▼
        vmaf flush → 补齐全部帧分数
                ▼
        池化统计 (mean/harmonic/min/max)
                ▼
        回调 onFinished(Summary) → 结束
```

关键约束:
- **参考帧必须逐帧读取**,即使该帧判定为丢帧——解码器是顺序的,跳过会导致后续全部错位(开发中实际踩过的坑)
- 丢帧帧对不送入 libvmaf,只统计
- VMAF 单帧分数在送入下一帧后才就绪(motion 特征需要下一帧),因此采用"延迟一帧"查询,flush 后补齐

## 2. 帧对齐子流程

### 2.1 相似度度量

- 每帧亮度平面降采样为 32×32 **盒式均值**灰度图(Thumb)
- 相似度 = NCC(归一化互相关),∈[-1,1],对整体亮度/对比度变化不变
- 匹配阈值默认 0.6

### 2.2 绿屏标定模式

```
两端各自扫描开头:
  连续 ≥3 帧纯色帧(亮度标准差 < 3) → 判定绿屏段
  绿屏段结束后的第一帧 = 锚点
任一端检测失败 → 降级为内容自动匹配
锚点之后仍走单调匹配(处理传输中途丢帧)
```

### 2.3 内容自动匹配模式

**粗对齐**:取参考前 ~60 帧缩略图作为模板,在目标开头 ±10 秒范围内滑动,平均 NCC 最高的位置为初始偏移。

**单调序列匹配**(核心):

```
d = 目标起始帧
for 每个参考帧 r:
    在窗口 [d, d+16) 内找 NCC 最大的目标帧 j
    j 的 NCC < 0.6        → r 判定丢帧, d 不动
    NCC(r+1, j) > NCC(r, j) → r 实为丢帧(消歧), d 不动
    否则                   → 匹配 (r, j), d = j+1
```

消歧规则是处理"参考帧率 > 目标帧率"的关键:丢帧处当前参考帧与其后一帧都和同一目标帧相似,只有比较两者才能正确判丢。

**冻结统计**:相邻两次匹配之间被跳过的目标帧数 = 画面重复(冻结/降帧)帧数。

### 2.4 不对齐模式

`refStart = distStart = 0`,仍走单调匹配但期望 1:1;帧数不一致时以短者为准。

## 3. VMAF 评分子流程 (VmafEvaluator)

```
vmaf_init(threads, subsample)
vmaf_model_load (内置名) 或 vmaf_model_load_from_path (json)
vmaf_use_features_from_model
循环: vmaf_picture_alloc → 填充 Y/U/V → vmaf_read_pictures(index) → unref
vmaf_read_pictures(NULL, NULL, 0)  // flush
vmaf_score_at_index(i)             // 逐帧
vmaf_score_pooled(MEAN/HARMONIC_MEAN/MIN/MAX)
vmaf_model_destroy / vmaf_close
```

## 4. 预处理流程 (PreprocessTab)

```
选择输入 → ffprobe 获取源分辨率/帧率/时长
   │
   ├─ 勾选绿屏:
   │   ffmpeg -i in -f lavfi -i color=green:s=WxH:r=FPS:d=5
   │   -filter_complex "[0:v]scale=W:H,fps=FPS[main];[1:v][main]concat=n=2:v=1[out]"
   │   -map "[out]" -c:v libx264 -b:v <码率> -pix_fmt yuv420p out.mp4
   │
   └─ 仅转码:
       ffmpeg -i in -vf scale=W:H -c:v libx264 -b:v <码率> -pix_fmt yuv420p out.mp4

进度: 解析 stderr 中 time=HH:MM:SS.xx, 按时长百分比更新进度条
```

要点:
- 绿屏段分辨率/帧率与源一致,保证 concat 顺利
- 绿屏从 GOP 起点开始编码,天然是关键帧边界
- 输出统一 yuv420p / H.264,兼容性最好

## 5. CLI 流程

`vmaf_tool --cli ref dist [--model ...] [--align ...]`
与 GUI 共用同一 `Pipeline`,仅回调改为 stdout 打印,用于脚本化批量测试与回归验证。

## 6. 验证流程 (开发期)

| 用例 | 构造 | 预期 |
|---|---|---|
| 自比对 | ref vs ref | VMAF ≈ 99+,映射 1:1 |
| 同帧率压缩 | crf34 重编码 | VMAF ≈ 87,无丢帧 |
| 降帧 | fps 30→24 | 丢帧位置周期出现(每 5 帧丢 1),分数与同帧率基准一致 |
| 绿屏 | 片头 5s 绿屏 + 降帧 | 锚点 = 绿屏结束帧,结果与内容匹配一致 |
