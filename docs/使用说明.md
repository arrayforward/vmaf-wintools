# 使用说明

## 1. 运行环境

- Windows 10/11 64 位
- 无需安装,直接运行 `vmaf_tool.exe`(所有依赖 DLL 与模型已随 exe 同目录打包)
- 预处理功能需要外部 `ffmpeg.exe`(可自动从 PATH 查找,或界面手动指定)

## 2. 典型测试流程

完整的"云侧直播 → 端侧录屏"画质测试分四步:

### 步骤 1:生成帧号片源(预处理 Tab)

1. 打开工具,切到 **视频预处理** Tab
2. 在 **生成帧号片源** 分组选择输入视频与输出路径(CRF 默认 14)
3. 点击 **开始生成**,工具调用同目录 `marker_burn.exe` 逐帧烧录 QR 帧号标记

> 将此视频放到云侧播放。QR 帧号为两端提供精确到帧的对齐依据,并支持自动裁剪掉黑边/UI。
> 如需调整分辨率/码率适配客户端屏幕,可先用上方的转码功能处理再烧码。

### 步骤 2:采集两端视频

- **参考视频**:烧码后的片源本身(或云侧编码前的录制)
- **目标视频**:端侧实际接收画面——可用 **采集** Tab 通过 adb 定时截屏(输出递增 PNG 序列文件夹),或端侧录屏

### 步骤 3:评估(画质评估 Tab)

1. 参考片源固定为 `ai_game_1080p60.mp4`(与 APK 内置片源同一份),自动从程序目录解析,只读显示;只需选择 **目标视频**(也可以是采集 Tab 输出的截图文件夹)
2. 选择 **模型**(默认 `vmaf_v0.6.1`,4K 内容选 `vmaf_4k_v0.6.1`)
3. 点击 **开始评估**,可随时 **停止**

> 对齐与裁剪全自动:两端帧号识别率均 ≥80% 时按 QR 帧号精确对齐,并由 QR 外接框反推视频区域自动裁剪(含黑边吸附细化);识别率不足会直接报错,提示先用 marker_burn 生成片源。
>
> 目标是**截图文件夹**时按采样模式处理:只统计匹配上的帧对,未采到的参考帧不计丢帧(丢帧恒为 0)、不打逐帧日志;冻结统计保留;进度按匹配对数推进;曲线 x 轴为"有效样本"序号。

### 步骤 4:查看与导出结果

- **结果栏**:VMAF mean / harmonic mean / min / max,丢帧数,冻结帧数,帧号覆盖率,冻结段统计
- **VMAF 曲线**:只画有效样本(丢帧不进图,折线直接连接相邻样本);x 轴视频模式为参考帧号、采样模式(截图文件夹)为有效样本序号;点击任意位置在日志中查看该帧明细;滚轮缩放、右键拖动平移
- **日志**:逐帧分数与丢帧事件实时滚动
- **导出 JSON / CSV**:逐帧明细(参考帧号、目标帧号、状态、VMAF 分)

## 3. 命令行模式

适合脚本化批量测试:

```bat
vmaf_tool.exe --cli [参考视频] <目标视频> [选项]
```

参考视频可缺省,缺省时自动解析程序目录下的 `ai_game_1080p60.mp4`。

| 选项 | 说明 | 默认 |
|---|---|---|
| `--model <名称或json路径>` | 模型 | vmaf_v0.6.1 |
| `--yuv-size 1920x1080` | .yuv 输入分辨率 | 1920x1080 |
| `--threads N` | 线程数,0=自动 | 0 |

输出:进度、池化分数、逐帧明细(stdout)。

## 4. 输入格式

- 容器格式:mp4 / mkv / avi / mov / flv 等(FFmpeg 解码,统一转 yuv420p)
- 原始格式:`.yuv`(yuv420p 8bit),需在界面 "YUV尺寸" 处填写分辨率
- 截图文件夹:采集 Tab 输出的 PNG 序列(目标输入专属,按 image2 序列读取,走采样模式)

## 5. 结果解读

| 指标 | 含义 |
|---|---|
| VMAF mean | 平均分,>90 优秀,70-90 良好,<50 明显劣化 |
| harmonic mean | 谐波平均,对低分帧更敏感,反映最差体验 |
| 丢帧率 | 参考帧在目标中找不到匹配的比例(网络丢帧/严重卡顿);采样模式(截图文件夹)下未采样不计丢帧,恒为 0 |
| 冻结帧 | 目标连续重复同一画面的帧数(画面卡住) |

注意:
- VMAF 只反映"匹配上的帧"的画质,**丢帧/冻结需结合统计指标一起看**。
- 自动裁剪后两端尺寸不一致时取较小者为比较分辨率(较大端降采样);v0.6.1 模型按 1080p 观看条件校准,**小分辨率比较下分数语义有偏差**,绝对分仅供参考,相对比较仍有效。
- 端到端实测(真机本地播放 + adb 截图):QR 帧号识别率 100%、对齐正确率 100%;VMAF 绝对分受显示缩放滤波影响——竖屏 0.56x 显示下约 75 为测量上限,基准验证建议用横屏或分辨率匹配的设备。

## 6. 常见问题

**Q: 分数异常低(<40)?**
A: 大概率是两端内容不对应(片源选错),或采集画面被严重遮挡导致帧号识别率不足。确认两端是同一内容。

**Q: 提示"未检测到帧号标记"?**
A: 片源未经 marker_burn 烧码,或采集画面分辨率过低/QR 被遮挡导致识别率不足 80%。用预处理 Tab 的"生成帧号片源"重新制作片源。

**Q: 提示"没有匹配到任何帧对"?**
A: 两端帧号没有交集——确认参考与目标是同一次测试的片源/采集。

**Q: 预处理提示找不到 ffmpeg?**
A: 在预处理 Tab 手动指定 ffmpeg.exe 路径。

**Q: 4K 视频评估慢?**
A: 增大线程数;或先用预处理 Tab 转码降低分辨率再烧码评估。
