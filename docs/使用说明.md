# 使用说明

## 1. 运行环境

- Windows 10/11 64 位
- 无需安装,直接运行 `vmaf_tool.exe`(所有依赖 DLL 与模型已随 exe 同目录打包)
- 预处理功能需要外部 `ffmpeg.exe`(可自动从 PATH 查找,或界面手动指定)

## 2. 典型测试流程

完整的"云侧直播 → 端侧录屏"画质测试分四步:

### 步骤 1:预处理源视频(预处理 Tab)

1. 打开工具,切到 **视频预处理** Tab
2. 选择原始视频(如游戏游玩录像)
3. 勾选 **片头插入绿屏**,默认 **5 秒**
4. 选择输出分辨率(默认 `1920x1080`)与码率(默认 `5000 kbps`),以适配客户端屏幕
5. 点击 **开始处理**,生成带绿屏标定的新视频

> 将此视频放到云侧播放。绿屏为两端提供了时间对齐锚点。

### 步骤 2:采集两端视频

- **参考视频**:预处理后的视频文件本身(或云侧编码前的录制)
- **目标视频**:端侧实际接收画面的录屏(如 60fps 屏幕录制)

### 步骤 3:评估(画质评估 Tab)

1. 分别选择 **参考视频** 和 **目标视频**,界面自动加载首帧预览
2. 在预览图上 **拖拽框选裁剪区域**(默认中心 1/2,避开黑边/状态栏):
   - 勾选"联动框选"时两端同步(分辨率需一致)
   - "恢复默认"回中心 1/2,"全画面"不裁剪
3. 选择 **模型**(默认 `vmaf_v0.6.1`,4K 内容选 `vmaf_4k_v0.6.1`)
4. 选择 **对齐模式**:
   - 片头加了绿屏 → 选 **绿屏标定**
   - 没加绿屏 → 选 **内容自动匹配**
   - 两端天然帧对齐(如纯压缩对比) → 选 **不对齐**
5. 点击 **开始评估**,可随时 **停止**

### 步骤 4:查看与导出结果

- **结果栏**:VMAF mean / harmonic mean / min / max,丢帧率,冻结帧数
- **VMAF 曲线**:点击任意位置跳转到该帧,上方双画面同步显示;滚轮缩放、右键拖动平移;红色竖线 = 丢帧
- **日志**:逐帧分数与丢帧事件实时滚动
- **导出 JSON / CSV**:逐帧明细(参考帧号、目标帧号、状态、VMAF 分)

## 3. 命令行模式

适合脚本化批量测试:

```bat
vmaf_tool.exe --cli <参考视频> <目标视频> [选项]
```

| 选项 | 说明 | 默认 |
|---|---|---|
| `--model <名称或json路径>` | 模型 | vmaf_v0.6.1 |
| `--align none\|green\|content` | 对齐模式 | content |
| `--yuv-size 1920x1080` | .yuv 输入分辨率 | 1920x1080 |
| `--threads N` | 线程数,0=自动 | 0 |

输出:进度、池化分数、逐帧明细(stdout)。

## 4. 输入格式

- 容器格式:mp4 / mkv / avi / mov / flv 等(FFmpeg 解码,统一转 yuv420p)
- 原始格式:`.yuv`(yuv420p 8bit),需在界面 "YUV尺寸" 处填写分辨率

## 5. 结果解读

| 指标 | 含义 |
|---|---|
| VMAF mean | 平均分,>90 优秀,70-90 良好,<50 明显劣化 |
| harmonic mean | 谐波平均,对低分帧更敏感,反映最差体验 |
| 丢帧率 | 参考帧在目标中找不到匹配的比例(网络丢帧/严重卡顿) |
| 冻结帧 | 目标连续重复同一画面的帧数(画面卡住) |

注意:VMAF 只反映"匹配上的帧"的画质,**丢帧/冻结需结合统计指标一起看**。

## 6. 常见问题

**Q: 分数异常低(<40)?**
A: 大概率是没对齐。确认对齐模式是否选对;内容自动匹配失败时,改用绿屏标定重试。

**Q: 提示"没有匹配到任何帧对"?**
A: 两端内容差异过大(如录屏有大面积 UI 遮挡),调整裁剪区域只保留画面主体。

**Q: 预处理提示找不到 ffmpeg?**
A: 在预处理 Tab 手动指定 ffmpeg.exe 路径。

**Q: 4K 视频评估慢?**
A: 增大线程数;或先用裁剪缩小评估区域。
