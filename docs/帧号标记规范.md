# 帧号标记规范 v1

云游戏画质评测方案中，测试片源的每一帧都烧录一个二维码帧号标记。
采集端（adb 截图或录屏）解码该二维码即可得到 `源帧号 → 采集帧` 的精确映射，
替代传统的绿屏/NCC 内容对齐，天然处理丢帧、冻结、乱序。

## 标记定义

- **载体**：QR Code，载荷 = 帧号的十进制字符串（8 位，左侧补零，如 `00000123`）
  - 帧号范围 0 ~ 99999999（60fps 下约 19 天，足够）
  - 纠错等级 **H**（可容忍 30% 面积损坏），自动选最小版本（8 位数字 → version 1, 21×21 模块）
- **位置**：源视频帧右下角，静区（quiet zone）4 模块，静区外缘距帧边缘 2 模块
- **模块尺寸**：`m = max(8, round(W/160))`，向下取偶数
  - 1080p: m=12，含静区占 29×12=348px；720p: m=8，占 232px；1440p: m=16，占 464px
  - （v1 初版为 W/240，实测 1Mbps+缩放可解码，为更低码率/更小显示窗口预留余量而加大）
- **颜色**：码区黑模块 Y=16、白模块/静区 Y=235，整个标记矩形 U=V=128

## 库选型

- 烧录（编码）：Nayuki qrcodegen（单文件 C++，MIT），vendor 到 `third_party/qrcodegen/`
- 解码：quirc（C 库，ISC），vendor 到 `third_party/quirc/`
  - quirc 解码成功即视为有效（内部已做 RS 纠错和格式校验）

## 解码流程

1. 灰度化（YUV 帧直接用 Y 平面；RGB 截图转灰度）
2. quirc 扫描整图找 QR 码，解码载荷
3. 校验载荷为 8 位纯数字 → 帧号；否则 `valid=false`
4. 由 quirc 返回的 QR 外接框 + QR 在源帧中的名义尺寸（29×m），反推缩放比和偏移，
   得到截图中视频区域的矩形（支持缩放和信箱黑边，假设无旋转），用于自动裁剪
   - 注意：不得假设输入图就是完整视频帧；缩放比必须由 QR 实测尺寸 ÷ 名义尺寸算出
5. 解码失败 → `valid=false`，该样本不计入打分，计入未识别统计

## 配套指标

从 `(采集时刻, 帧号)` 序列可推导：

- 画质分时间序列（逐样本 VMAF）
- 卡顿/冻结：相邻样本帧号相同
- 丢帧率：缺失帧号数 / 覆盖区间长度
- 端到端延迟（近似）：采集时刻 - 帧号对应的片源时间（需时钟对齐）

## 工程约束

- 片源制作：PNG 序列离线烧码 → 无损 H.264 (`libx264 -qp 0`) 封装
- 云端播放：专用 Android 播放器 App（无网络权限、全屏循环）
- 端侧采集：Windows 工具经 adb `screencap` 定时截图 / `screenrecord` 分段录屏
- 比对：Windows 工具内解码帧号 → 与片源逐帧 VMAF → benchmark 报告
